## Chronological history

### P01-P05 — specialize runtime ownership and 128 m memory policy

```text
perf(terrain3d): specialize runtime storage for fixed 128m regions

- establish fixed-region memory/capacity contracts
- separate cold owner allocation from hot resident selection
- replace runtime growth with owner-controlled capacity decisions
- tighten fixed pools and systems-C ownership boundaries
- preserve authoring flexibility outside hot runtime paths
```

### P06 — generation-gated publication

```text
perf(rd): gate Terrain3D publication on source-owned generations

- replace repeated source fingerprints/scans with producer generations
- track material, texture-layer, mesh, regional-lighting and ocean publication
- repair physical-page-table generation independence
- invalidate deferred mesh commits and authoring replacements correctly
```

### P07 — exact GPU upload accounting and bounded admission

```text
perf(gpu-cache): make Terrain3D page uploads exact and time-budgeted

- account finite mip chains and auxiliary Middle/shadow planes exactly
- add elapsed-time byte and update-call token admission
- preserve Editor Authoring live fallback while runtime remains cooked-authoritative
- make GPU-page capacity non-destructive to Near/Middle/Far render tiers
- expose adjustable aggregate and GPU-page budgets
```

### P07 regressions — startup, residency, cooking and height-minimum recovery

```text
fix(terrain3d): repair startup residency and runtime-page authoring regressions

- fix pre-init GPU-cache owner dereference
- make height the minimum functional terrain rendering requirement
- isolate terrain rendering from companion instance/ocean failures
- recover renderer state after transient publication gaps
- recook legacy/stale/incompatible runtime pages instead of aborting the dataset
- generate Middle runtime pages at the frozen runtime divisor in Editor Authoring
- permit canonical collision borders to cross genuinely unauthored world edges
- synchronize the native/editor build contract
```

### P08 — RenderWorld prepare/submit reuse

```text
perf(render-world): reuse pass-independent camera visibility preparation

- split compute visibility/VT preparation from raster pass submission
- cache equivalent prepared views across OPAQUE/MOTION callbacks
- key reuse by frame, viewport, view state and scene/terrain/culling generations
- keep pass kind and draw-list identity out of the compute cache key
- add prepare/reuse/raster-submit runtime telemetry
- preserve allocation-free hot-path ownership
```
